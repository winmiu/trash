# Fair Dice · 公平骰（SillyTavern 扩展） v1.7.0

独立于角色卡、世界书和正则的 **跑团裁定 + 真实掷骰 + 加权事件** 前端扩展。作者署名：winmiu。

在「扩展 → 公平骰」的「当前聊天启用」下方，展开 **运行日志** 即可查看。日志默认收起，按聊天保存最近 20 次运行，最多保留最近使用的 40 段聊天。日志从 v1.4.0 加载后开始记录。

## 正文内判定 · 一次请求

新安装后，在当前聊天启用公平骰即可使用。旧版升级会保留已选模式，展开「判定设置 → 裁判方式」可切到「正文内判定 · 一次请求」。酒馆照常发起正文请求，扩展在本机准备候选骰点和抽签顺序。正文模型在这一次生成里读取当前角色卡、已进入上下文的世界书、聊天和本轮输入，决定是否用骰，然后写剧情。

事件走向和 NPC 反应分别按剧情调整。每个启用条目的基础权重可临时乘 **0.5、1 或 2**，再按组换算为概率。例如「协商」和「拒绝」基础权重各 10，角色刚与对方达成互信时，模型可以把协商调为 2 倍、拒绝调为半倍。这轮的比例就是 80% 和 20%。每个新回合重新读已发生的剧情。调整只作用于当前聊天的本轮抽签，零权重和关闭的项目始终不参加。

模型随正文附一条短记录，列出采用的类别、系数、抽签编号和一句依据。扩展从回复末尾取走自己的记录，在本地核对抽签顺序，再把已确认的结果显示在面板和日志。漏写、数据截断或编号不符会记为「未确认」，正文保留，扩展不会追问模型。由于同一个模型能看到抽签顺序，日志能核对它申报的系数与编号是否一致，无法证明它先定系数再看候选，也不会逐句核验剧情。

行动检定按本机 d100 和难度表执行。交锋沿用本地战力规则，双方战力未知时默认暂缓硬判，手动填写战力后可判。重新生成会复用同回合已确认的结果。单次模式使用正文连接，额外裁判请求为 0。

## 前置裁判

选择「前置 AI · 精简上下文」或「前置 AI · 完整上下文」可先评估，再生成正文。精简模式会从酒馆已组好的聊天补全请求中提取本轮玩家输入（最多 2200 字符）、此前最多四条对话和相关设定片段。输出上限为 1024 tokens，空回复或 JSON 错误重试时最多用 2048 tokens。遇到媒体或无法定位玩家输入时沿用完整上下文。

遇到早期约定、复杂世界书或多人关系，可在「判定设置 → 裁判方式」选择「前置 AI · 完整上下文」，再到「手动判定」点击「AI 评估场景」。

每次运行按时间列出酒馆的生成信号、是否进入判定、裁判依据、实际骰点或加权抽签结果，以及是否把指引交给酒馆。重新生成会注明是否复用了骰点。模型连接失败、回复格式错误、战力资料不足和正常无须掷骰会分别显示。查看日志不会发起模型请求。

自动判定和「AI 评估当前场景」在首次请求失败后，分别等待 1、2、4 秒再试，最多重试 3 次。日志逐次显示失败原因和重试次数。任一次拿到有效裁定就结束请求，只在裁定需要时掷骰一次。酒馆发出停止信号或切走当前聊天时会结束本次评估。

四次都失败时，本次跳过掷骰。之后即使在同一回合点「重新生成」，也会真正重新请求裁判。旧版保存的失败记录同样适用。成功的判定和骰点仍会保留，包括裁判确认无须掷骰的回合。

运行日志会显示本轮裁判使用的连接。支持请求准备事件的接口还会显示准备好请求到收到回复之间的耗时。

### 前置裁判的调用次数

开启前置 AI 裁判后，新回合先请求一次裁判，等它返回再由酒馆请求一次正文。裁判决定无须掷骰时也要先完成这次评估。本地规则模式通常只有正文一次模型请求。同回合重新生成如已取得有效结果，直接复用，只有正文需要再请求。

### 配置独立裁判 API

展开「扩展 → 公平骰 → 判定设置」，将「裁判 API」从「跟随正文」切换为「独立 API」。填入 OpenAI 兼容接口的地址（通常以 `/v1` 结尾）、裁判模型名和该接口自己的密钥。可为裁判选用响应较快的模型。精简与完整上下文均支持独立连接，手动评估也使用这里选定的连接。

请求由运行酒馆的设备转发，接口地址须可从该设备访问。地址和模型保存在扩展设置中。密钥仅保留在当前酒馆账号的浏览器标签页，关闭标签页或更换地址后需重新填写。本机免密服务可以留空。独立模式只向填写的接口发送裁判请求。配置缺失会在日志提示，接口失败按现有规则重试。正文始终由酒馆当前选定的连接生成。

1. **独立裁定**（简短JSON）：是否有必要掷骰？当前是普通叙事、行动检定还是战斗交锋？是否出现自然转场或NPC尚未决定的选择？角色能力、人数、装备、难度和风险有哪些客观依据？
2. **程序掷骰**：当需要检定时，插件通过浏览器随机数（优先 `crypto.getRandomValues`）执行权重抽签或d100。AI不自行决定骰点，也不在掷骰前决定输赢。
3. **注入结果**：生成主回复前，用官方扩展接口 `setExtensionPrompt` 告诉AI裁定结果，要求遵守、不代替玩家行动、不展示骰子算法。不会修改角色卡/MVU/原有聊天消息。

独立裁定只保存**可检查的简短理由与数值依据**，不是请求或展示模型的私密思维链。最终叙事模型仍可能偏离注入规则；本版本不会自动检查并重生成不服从骰子的回复。

## 安装

**A. GitHub仓库安装（最适合分享）**

打开 SillyTavern 的「扩展 → 安装扩展」，粘贴 `https://github.com/winmiu/trash.git`，选择当前用户或所有用户。安装后刷新页面，打开「扩展 → 公平骰」。运行酒馆的设备需要安装 Git。

**B. 无GitHub的本地安装**

解压ZIP后，将根目录改名为 `fair-dice` 并放入：
- `SillyTavern/data/<用户名>/extensions/fair-dice/`（当前用户）
- 或 `SillyTavern/public/scripts/extensions/third-party/fair-dice/`（所有用户）

请确认 `fair-dice/manifest.json` 直接存在；刷新或重新启动酒馆，然后在「扩展」中找到“公平骰”。**不要放到正则列表、角色脚本或世界书里**。

## 用法

默认**当前聊天不开启**。新安装预选正文内判定，旧版升级保留原来的裁判方式。

进入聊天，在「扩展 → 公平骰」开启「当前聊天启用」。有结果时，开关下方会显示最近判定。其余面板默认收起。

- **运行日志**记录耗时、裁判依据、骰点和错误。
- **判定设置**可选择正文内判定、精简或完整的前置裁判、本地规则，并设置允许的检定类型。这些选项用于所有已启用的聊天。
- **手动判定**可以为当前聊天指定模式、战力和难度，主动评估场景，或锁定下一次回复的结果。
- **事件与反应权重**可为当前聊天选择预设。展开「事件走向」或「NPC 反应」可编辑对应项目，直接输入权重即可看到概率。

关闭当前聊天开关后，插件清除自己的提示词注入；其他聊天不受影响。

### 判定行为

- **本轮无需骰子**：闲聊、明确的常规行为、已确定的事实，原则上都不摇骰，也不强行加戏。
- **事件方向**：只在合适的自然转场抽事件权重；NPC反馈只有在存在真实未决选择时才独立抽取。默认65%“延续当前情境”。
- **行动检定**：依据难度以及已知的准备/环境修正计算d100成功率。客观不可能的行动成功率为0%。
- **战斗检定**：按0—100有效战力、人数、装备地形与伤势，一骰只判**一次交锋**。采用“自动适配世界观”时，现代现实背景不强行套武侠阶位；武侠背景可采用严格五阶差。不允许一个人无理由正面击败成建制大量敌人。
- **没有战斗等级**：前置 AI 裁判在有文本证据且具有中高置信度时可临时估计有效战力。正文内判定使用本机已有的战力数据。战力缺失时默认暂缓胜负，也可手动填写。
- **公平原则**：NPC可以有正当理由帮助或拒绝玩家；不会仅因为是`{{user}}`就获胜，也不刻意制造失败。
- **重生成**会沿用同一回合已成功的裁判结果和骰点。上次评估最终失败时，再次生成会重新评估。修改用户消息或进入新回合也会重新判定。

### 预设与面板

可编辑事件名称、说明、启用状态和基础权重。每组按已启用项目的有效权重计算百分比。正文内判定使用本轮剧情系数，其他模式使用基础权重。连续成功或失败的次数不参与调权。

### 费用、隐私与兼容

- 正文内判定只增加正文请求里的提示和简短记录。前置 AI 评估通常额外请求一次所选裁判接口，含自动重试最多四次。
- 独立裁判服务会收到用于判定的玩家输入、对话和设定。选择完整上下文时发送酒馆为该次评估准备的完整剧情文本。
- 前置模式收到无效 JSON 会记录错误并自动重试。正文内判定缺少有效记录时只记入日志。
- 不保证与所有高强度预设/重写插件兼容。建议停用同时对同一段叙事做判定的其他扩展，防止重复骰子和互相矛盾。
- 不支持读取任何模型内部私有思维链；只使用有限的JSON结果和可见依据摘要。

## v1.3 更贴近多角色卡跑团的改动

- **每个聊天独立保存事件权重和NPC反馈权重**：武侠卡与现代都市卡互不污染。默认按公平中立模板初始化。
- **前置AI裁判预选开启，聊天开关仍默认关闭**：一旦启用当前聊天，先判断有没有必要摇骰；普通聊天和无风险行动可以不摇。额外消耗一次模型调用；如不需要可取消。
- **没有等级时审慎估计**：裁判须说明行动方与对手的能力来源、具体事实及置信度。无法举证时返回未知并暂缓胜负骰。
- **防错初始化**：扩展在APP_READY已触发后开启仍能初始化UI。
