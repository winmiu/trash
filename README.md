# 公平骰 v2.0.0

开启「扩展 → 公平骰 → 当前聊天启用」后照常发消息。新楼第一次生成时，公平骰把骰点和自适应规则放进正文输入。主模型在同一条回复里先给一条简短裁定，再按主预设写故事。扩展收起裁定，核对骰表，把依据、条件和结果写入运行日志。

## 每轮怎样判定

- **先判有没有悬念。** 闲聊、尚未实行的打算或已经确定的事直接承接。行动和交锋只判当下目标的成败，具体后果由主预设写。
- **行动看任务和人。** 同一把待修的锁，任务门槛相同。熟悉这种锁、工具齐全，或手受伤、工具短缺，都会影响当下的判定。
- **交锋看这一合争什么。** 抢先拦住对方与正面压制对方，可以有不同的强弱关系。没写战力数值也能用双方的训练和过往表现判定，再考虑伤势、位置及实际人数。确实缺少关键依据时暂缓定胜负。
- **事件看局势，NPC 看动机。** 转场时根据时间、地点和未完事务评估事件。人物确有选择时，按关系、承诺和代价评估反应。各项每轮重新采用两倍、原值或一半权重，和设定冲突的条目跳过。面板中的基础权重仍可按聊天调整。
- 同一条玩家消息视作一楼。裁定一经确认，重生成、续写或生成新的候选回复时，直接把这份简短裁定放进正文输入。同楼保留骰点、权重候选和已确认的裁定，普通生成只使用酒馆原有的正文请求。

## 查看运行情况

展开「运行日志」可看到本楼实选的分支、模型引用的一句剧情事实，以及本机核验的结果。交锋显示强弱、人数、临场修正、骰点和阈值；事件和 NPC 反应显示选中项及权重调整。「查看本次实际注入的内容」可核对该次正文请求使用的文本。

如果模型漏写裁定、所报成败与骰表不符或生成中止，日志会标明本次未确认。正文保留，本楼骰点继续沿用；扩展不会为此追加模型请求。

## 手动重新摇骰子

想换结果时，保留原来的玩家消息，可以先删除那条 AI 回复。在「运行日志」点「重新摇骰子」，再让酒馆生成。本楼旧裁定随手动重掷解除，重新掷出的点数或成败有可能和原来相同。按钮本身不会删除消息或生成正文。

## 安装

在酒馆「扩展 → 安装扩展」粘贴 `https://github.com/winmiu/trash.git`。已安装时使用扩展管理中的更新按钮，然后刷新页面，在公平骰面板底部确认版本为 v2.0.0。

手动安装可将 ZIP 解压到酒馆的 `data/<用户名>/extensions/fair-dice/`，确保该目录直接包含 `manifest.json`。若原来已安装，请使用原扩展目录，以免重复加载。
