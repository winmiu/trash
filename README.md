# 公平骰 v2.2.0

开启「扩展 → 公平骰 → 当前聊天启用」后照常发消息。默认每楼使用一次正文请求。扩展提供本楼骰点、简短规则和候选，正文模型按角色卡与剧情判定并依预设写故事。裁定可附在回复末尾，由扩展核对并收进日志。

## 独立裁判

在「公平骰 → 独立裁判」使用「启用独立裁判」开关。关闭时照常在一次正文请求中判定。开启时，新楼先请裁判选条件，扩展按本楼骰点算出成败，再将结果交给正文。新楼共两次请求，已确认的同楼裁定只需一次正文请求。

- **跟随主 API** 使用酒馆此时选中的连接和模型。此时裁判和正文仍是两次请求。
- **独立 API** 填写 OpenAI 兼容接口地址、模型名以及该接口需要的密钥。第三方连接使用自己的凭据。密钥绑定接口地址，仅保留在当前标签页。
- **酒馆连接** 也可沿用已保存的聊天补全连接。旧版已选择裁判连接的用户升级后沿用该选择和开启状态。新安装默认关闭独立裁判。

独立裁判只收到裁判指令、限长的角色与玩家资料、场景和最近最多五条对话。仅注入正文的世界书条目不会发给独立裁判。裁判失败会记入日志，正文继续。

## 每轮怎样判定

- **先判有没有悬念。** 闲聊、尚未实行的打算或已经确定的事直接承接。行动和交锋只判当下目标的成败，具体后果由主预设写。
- **行动看任务和人。** 同一把待修的锁，任务门槛相同。熟悉这种锁、工具齐全，或手受伤、工具短缺，都会影响当下的判定。
- **交锋看这一合争什么。** 抢先拦住对方与正面压制对方，可以有不同的强弱关系。没写战力数值也能用双方的训练和过往表现判定，再考虑伤势、位置及实际人数。确实缺少关键依据时暂缓定胜负。
- **事件看局势，NPC 看动机。** 转场时根据时间、地点和未完事务评估事件。人物确有选择时，按关系、承诺和代价评估反应。各项每轮重新采用两倍、原值或一半权重，和设定冲突的条目跳过。面板中的基础权重仍可按聊天调整。
- 同一条玩家消息视作一楼。裁定一经确认，重生成、续写或生成新的候选回复时，直接把这份简短裁定放进正文输入。同楼保留骰点、权重候选和已确认的裁定，普通生成只使用酒馆原有的正文请求。

## 查看运行情况

行动或交锋经核验后，AI 回复下方会有一行可核对的小字。例如「行动 · d100=88，成功阈值 1%，88 > 1，失败」。骰点等于阈值也算成功。相同数字会出现在运行日志里。若模型所报成败或阈值有误，但条件完整，会单列本机复核；若条件不足，则标明阈值未确认。

展开「运行日志」可看到本楼选用的分支、引用的事实，以及核验结果。聊天补全模式在酒馆组装完预设后放入本楼提示，并保留末尾的助手预填。日志区分「已准备」和「已在酒馆发往接口的正文请求中核对到公平骰」。后者表示发送前的请求中确实包含提示；模型是否按要求判定，看随后记录的结果。也可点 AI 回复上的提示词明细核对位置。

如果模型漏写裁定、所报成败与骰表不符或生成中止，日志会标明本次未确认。正文保留，本楼骰点继续沿用；扩展不会为此追加模型请求。

## 手动重新摇骰子

想换结果时，保留原来的玩家消息，可以先删除那条 AI 回复。在「运行日志」点「重新摇骰子」，再让酒馆生成。本楼旧裁定随手动重掷解除，重新掷出的点数或成败有可能和原来相同。按钮本身不会删除消息或生成正文。

## 安装

在酒馆「扩展 → 安装扩展」粘贴 `https://github.com/winmiu/trash.git`。已安装时使用扩展管理中的更新按钮，然后刷新页面，在公平骰面板底部确认版本为 v2.2.0。

手动安装可将 ZIP 解压到酒馆的 `data/<用户名>/extensions/fair-dice/`，确保该目录直接包含 `manifest.json`。若原来已安装，请使用原扩展目录，以免重复加载。
